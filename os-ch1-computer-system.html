Quick recap from the lecture

  • Basic elements: processor, main memory, I/O modules, system bus. Instruction cycle = fetch (PC → instruction, PC + 1) then execute.
  • Interrupts improve processor utilization. Classes: program, timer, I/O, hardware failure. With interrupts, an interrupt stage follows execute (if interrupts are enabled).
  • Interrupt processing: finish the current instruction → acknowledge → push PSW and PC → load handler PC → save state → handle → restore state → restore PSW and PC.
  • I/O techniques: programmed (processor polls) → interrupt-driven (processor still moves the data) → DMA (whole block; processor only at start and end).
  • Memory hierarchy: going down, cost/bit ↓, capacity ↑, access time ↑, access frequency ↓. Two-level: Ts = H·T1 + (1−H)(T1+T2). Locality makes it work.
  • SMP: similar processors sharing memory and I/O under one OS. Amdahl: S(n) = n / (1 + (n−1)f), max 1/f.

1.1Predict the output

Trace the fetch–execute cycle

This tiny machine has an accumulator (AC) and runs the program at address 300. What does it print?
Code
memory = {300: ("LOAD", 940), 301: ("ADD", 941), 302: ("STORE", 941), 303: ("HALT", None),
          940: 3, 941: 2}
PC, AC = 300, 0
while True:
    IR = memory[PC]          # fetch
    PC = PC + 1              # PC is incremented after each fetch
    op, addr = IR            # execute
    if op == "LOAD":
        AC = memory[addr]
    elif op == "ADD":
        AC = AC + memory[addr]
    elif op == "STORE":
        memory[addr] = AC
    elif op == "HALT":
        break
    print("PC =", PC, "IR =", op, addr, "AC =", AC)
print("memory[941] =", memory[941])
Your prediction
  1. Step 1. The PC moves to the next address right after the fetch, before the instruction runs.
  2. Step 2. LOAD 940 → AC = 3. ADD 941 → AC = 3 + 2.
  3. Step 3. STORE 941 writes AC back into 941. HALT stops before printing.
Show the answer
Output
PC = 301 IR = LOAD 940 AC = 3
PC = 302 IR = ADD 941 AC = 5
PC = 303 IR = STORE 941 AC = 5
memory[941] = 5

1.2Think & answer
Order the interrupt-processing steps
Put these in order: (a) processor pushes PSW and PC onto the control stack, (b) restore old PSW and PC, (c) device issues an interrupt, (d) processor finishes the current instruction, (e) save remainder of process state, (f) process interrupt, (g) processor loads new PC based on the interrupt, (h) processor signals acknowledgment, (i) restore process state information.
  1. Step 1. Hardware steps come first (5 of them), then software (4).
  2. Step 2. The current instruction is always finished before anything else happens.
  3. Step 3. The software side mirrors itself: save … process … restore … restore.
Show the answer
Answer
c → d → h → a → g (hardware) then e → f → i → b (software).

1.4Write code
Two-level memory calculator
Write access_time(H, T1, T2) using Ts = H·T1 + (1 − H)(T1 + T2). Print Ts for H = 0.5, 0.8, 0.9, 0.95, 0.99 and 1.0 with T1 = 0.1 µs and T2 = 1 µs.
  1. Step 1. A miss costs T1 + T2 because M1 is checked first.
  2. Step 2. Loop: for H in [0.5, 0.8, 0.9, 0.95, 0.99, 1.0]:.
  3. Step 3. Format with "%.3f".
Show the full solution
Solution
def access_time(H, T1, T2):
    return H * T1 + (1 - H) * (T1 + T2)

for H in [0.5, 0.8, 0.9, 0.95, 0.99, 1.0]:
    print("H = %.2f  Ts = %.3f us" % (H, access_time(H, 0.1, 1.0)))
Expected output
H = 0.50  Ts = 0.600 us
H = 0.80  Ts = 0.300 us
H = 0.90  Ts = 0.200 us
H = 0.95  Ts = 0.150 us
H = 0.99  Ts = 0.110 us
H = 1.00  Ts = 0.100 us
As H → 1, Ts → T1. That's why a small cache with a high hit ratio makes memory look almost as fast as the cache.

1.5Write code
Amdahl's law table
Write speedup(n, f) = n / (1 + (n − 1)f). Print the speedup for n = 1, 2, 4, 8, 16 with f = 0.05 and f = 0.1, and the limit 1/f for each.
  1. Step 1. Use two nested loops, or one loop per f.
  2. Step 2. The limit as n → ∞ is 1 / f.
Show the full solution
Solution
def speedup(n, f):
    return n / (1 + (n - 1) * f)

for f in [0.05, 0.1]:
    row = ["%.2f" % speedup(n, f) for n in [1, 2, 4, 8, 16]]
    print("f =", f, row, "max =", round(1 / f, 1))
Expected output
f = 0.05 ['1.00', '1.90', '3.48', '5.93', '9.14'] max = 20.0
f = 0.1 ['1.00', '1.82', '3.08', '4.71', '6.40'] max = 10.0
